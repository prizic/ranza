Trial record · RANZ-45 audit log hardening · PR #59

The audit log does what ADR 0031 says. The run around it found five defects.

Verdict: PARTIAL. 28 of 28 audit-log cases passed; 1 probe failed (C-29). Five FAILs: F-1 the People screen cannot change any role, F-2 Turkish server copy on /en after in-app navigation (app-wide), F-3 the refusal blames the Subscription, F-4 raw housekeeping facts, F-5 a rate-limited sign-in reads as a wrong password. 5 items UNVERIFIED — listed below, not hidden.

Failures

F-1 · The People screen cannot change anyone's role FAIL

Severity: high (Staff feature, found while exercising this one; it blocks the UI path to AL-S1-29). Choosing any role in a roster row — an Organization's own (Night auditor) or one Ranza ships (Front desk) — shows “That was refused.” and nothing changes; no staff.role_changed record is written.

Cause: apps/operator-workspace/src/server/staff.ts, changeStaffRole, passes the select's value <scope>:<key> (e.g. :front_desk) straight through as roleKey. The same file's roleFrom() splits that pair, and inviteStaffMember uses it; changeStaffRole does not. Fix: ...roleFrom(String(form.get("role") ?? "")) in place of roleKey: String(form.get("role") ?? ""). No browser test changes a role, and the integration suite calls the module directly, which is why nothing caught it.

Repro: sign in as an Owner → People → any row's Role select → pick another role → “That was refused.”

F-2 · On /en, pages reached by in-app navigation render their server copy in Turkish FAIL

Severity: medium, app-wide, not the audit log's alone. Clicking Audit log in the rail shows “Son işlemler: Deniz Otelleri”; clicking a record shows “Tüm kayıtlar”; People from the rail shows a Turkish subtitle. Reloading the same URL shows English. Client-rendered copy (table headers, filters) stays English, so each page is mixed. Every page calls getTranslations() with no locale, and requests from in-app navigation fall back to the default, Turkish. See C-29.

Repro: /en/today → click Audit log in the rail → read the line under the title.

F-3 · The refusal blames the Subscription FAIL

Severity: low (copy). A Staff Member without audit.read is told “This module is not in your Subscription — It appears here once your Organization subscribes…”. Audit is not subscription-gated (ADR 0031); the true reason is a missing permission, and only an administrator can grant it. The page reuses notEntitledTitle/notEntitledDescription. See C-04.

F-4 · A housekeeping record's details are shown raw FAIL

Severity: low. The housekeeping writer's facts appear as status → clean and previousStatus → dirty in every locale. features/audit-log/components/context-facts.tsx has no entries for these keys or values; the writer merged after the log. See C-12.

F-5 · A rate-limited sign-in says the password is wrong FAIL

Severity: low, outside the audit log. Signing in a fourth person within ten seconds returned HTTP 429 (confirmed with curl: {"message":"Too many requests. Please try again later."}) and the sign-in page showed “That email and password did not match.” Observed 3 times in the run log; no screenshot was taken of it.

Cosmetic, not counted: at 1400 px the Property filter reads “Every Property you reac…” and the search placeholder is cut off (visible in every list capture).
