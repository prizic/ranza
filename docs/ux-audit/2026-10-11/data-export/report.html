UX audit: Data export

Route /en/data-export (no sub-routes; the only linked endpoint is /api/data-export/[id]/download) · hosted staging, 2026-10-11 · persona: the owner or their accountant who needs "everything for the tax office" or "my guests list for the new software", and later needs to be sure nothing is trapped in the product · roles checked: Owner, Finance, Manager, Front Desk · mode: AUDIT ONLY, nothing was submitted, requested or downloaded.

Labels used throughout. verified I saw it in the running app. inferred I read it in code or docs and did not run it. unknown I could not find out.

Data state found: the Organization "Prizic Demo" has zero exports and zero schedules (verified, screenshots 01 and 04). So the in-progress, failed, expired and ready states, the history table, the download and the schedule table with rows were never on screen. Those are judged from the components and the feature docs only and are marked inferred. I did not request an export to create data, and I did not press Download, because a download writes a data_export.downloaded audit record in the same transaction (read in download/route.ts), which breaks the "records nothing beyond a read" condition.

1. Verdict

  1. Could the persona use it unaided? Partly. An owner who wants "all guests as a spreadsheet" can find the page, tick one box and ask. An accountant who wants "everything for 2025 for the tax office" cannot: there is no date range, no statement of scope, and the file is named export-1a2b3c4d.csv (inferred).
  2. Biggest risk: the form promises more than it delivers, and says nothing about what it leaves out. It offers five datasets to every role, pre-ticks two the Finance role may not be allowed to export, and does not say that several modules (staff, payroll, rates, food and beverage, inventory, maintenance) cannot be exported at all. "Nothing is trapped" cannot be confirmed from this page.
  3. Defect to fix first: a user without the permission who types the URL is told "This module is not in your Subscription", which is false (verified, DX-01).
  4. The default selection (Guests plus Reservations, as CSV) produces one stacked file with # dataset: section lines (inferred from render.ts, doc EXP-DEF-02), which a new system will not import as a guest list (DX-03).
  5. Counts: 21 findings: 1 blocks work, 6 cause errors, 6 slow me down, 8 polish. Thirteen rest at least partly on something I saw in the app; eight are inferred from code only.

4. Top changes

  1. I can see which datasets I am allowed to export and none of them is refused. Fix DX-02 and DX-01 together: gate the form by role and tell a no-permission user the truth.
  2. I can export one year, not all history, and the page says what scope I am getting (DX-04 now, date range in section 6). Removes the tax-office workaround and most of the "too large" dead end (DX-05).
  3. I get a file I can open and recognise: name with hotel, dataset and date (DX-08), headers and amounts a person can read (DX-10), and a clear note when several datasets share one CSV (DX-03).
  4. I know what is in the file before I trust it: record counts on the row (DX-09).
  5. I know what I am handling: a personal-data and 7-day-availability notice on the form (DX-06).
  6. I can tell what is not exportable and when I would lose access (DX-07).
  7. When an export fails or expires I can ask again in one click, and a stuck request says it is stuck (DX-11, DX-13).
  8. I can use it on a tablet (DX-14, DX-20).

5. Inconsistencies with sibling screens

  • Audit log: that page has date filters and is hidden from Finance; Data export has no date filter and offers the Audit log as a dataset to Finance, who cannot open that page (rail verified for Finance: no Audit log entry; the dataset checkbox is enabled, verified).
  • Headings: "Recent Export Records", "Active Export Schedules" are Title Case; Today uses sentence case ("Needs attention", "Today's movements").
  • Names: the dataset "Folios & Payments" is called "Finance" in the rail; the rail item for the audit log is "Audit log" and the dataset "Audit Log".
  • No-access message: this page reuses the "not in your Subscription" empty state also used for modules that are genuinely not subscribed (shared notEntitledTitle), so it cannot tell the two cases apart (inferred from page.tsx).
  • Back button (ADR 0035): present on this page, leads to Today, mirrors in Arabic (verified in 01, 07).
  • Date range: the sibling Date range field (flight-style picker) exists in packages/ui and is not used here.

6. Not built / needs backend work

Kept apart from the defects above.

  • Date range or any filter on an export (all rows, all dates). Not in edge-cases.csv at all, not in the roadmap line for data export. Needs a request column and the export functions to take it. Verified absence in the form; code confirms the request carries only datasets and format (requestExport input).
  • One file per dataset (zip): EXP-DEF-02, deferred. Until then, several datasets in CSV are stacked.
  • Object storage for files: EXP-DEF-01, deferred. Files are text in a database column, bounded at 25 MiB and 100,000 rows per dataset; the worker builds the file in memory before storing it (inferred from runner.ts, render.ts).
  • Exporting after a Subscription ends: EXP-DEF-03, an open owner decision. Today the answer is no data except the audit log.
  • A read permission for guests and reservations (front_desk.read): EXP-DEF-04, proposed. Source of the Finance refusal in DX-02.
  • Datasets for the rest of the product (staff, HR and payroll, rates, food and beverage, inventory, maintenance, housekeeping and guest-experience records): none exists in datasets.ts. Whether these are in scope is a product decision; blueprint section 13 forbids building ahead of a workflow, so this needs the owner.
  • Excel (.xlsx): removed on purpose (EXP-S1-08: "nothing ever wrote one"). CSV opens in Excel with a UTF-8 byte-order mark.
  • Delivery of scheduled exports (email, storage, webhook): nothing is sent; results stay in the page for 7 days.
  • Edit or delete a schedule; keep an export longer than 7 days; per-Property exports: not in the code or the edge cases.
  • Observability: the request and the download are audited (data_export.requested, data_export.downloaded in module.ts, and both are in the Audit log screen's action list). Completed and failed are published as events, not audit rows (EXP-S1-29, 30). No export existed on staging, so I could not look at a real audit entry (unknown).

7. What already works well and must not regress

  • Permission-aware rail verified: Owner and Manager see Data export and Audit log, Finance sees Data export only, Front Desk and Housekeeping see neither.
  • Plain dataset names and one-line descriptions in all three languages verified; Turkish and Arabic fully translated, Arabic mirrored including the back arrow and rail (screenshots 06, 07).
  • Back button at the leading edge of the page bar and the empty states with a sentence, not a blank table verified.
  • Turkish characters in CSV inferred: the file begins with a UTF-8 byte-order mark and the response is text/csv; charset=utf-8, so Excel will read İ, ş, ğ and Arabic names. Cells starting with =, +, -, @ are neutralised against formula injection, numbers (including negative reversals) are left alone, rows end in CRLF.
  • Loud failure over a quietly cut file inferred: above 100,000 rows or 25 MiB the export fails instead of handing over a truncated file that looks complete.
  • Failure reasons are sentences, not enum codes, in all three languages inferred (messages file).
  • Safe by construction inferred: the request button is disabled while sending and with no dataset ticked, Create Schedule is disabled with no name, the file body is never in the list query, the download is permission-checked and audited, and a render failure shows a retry page instead of an empty list (error.tsx).
  • Pending exports refresh themselves every 5 seconds without a reload inferred.
  • No horizontal overflow at 375 px verified.
