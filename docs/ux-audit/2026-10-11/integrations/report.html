Integrations: UX audit

Route /en/integrations · Hosted staging (main 4b15c30) · 2026-10-11 · Persona: owner or technically light manager who connects a booking channel or payment provider once and needs to know it is still working · Mode: audit only, nothing was changed.

1. Verdict

  • No. On staging this persona cannot use the feature at all. Owner and Manager both see Integrations in the rail, click it, and land on "This module is not in your Subscription". Verified, in English, Turkish and Arabic.
  • I could not see the real screen (cards, failed operations, Retry). The property does not have the integrations capability and I may not change data, so everything below about the populated screen is inferred from the code, the feature docs and the unit tests, and is labelled that way.
  • Even with the capability on, the page is a read-only status board that cannot do the persona's job. It has no Connect button, no credentials, no webhooks, no API keys and no delivery log. Nothing in the app or worker ever writes a connection or a failure (inferred, no callers of connectIntegration or recordFailure).
  • Biggest risk: the Retry button. By the code it marks a failure "resolved" and flips the connection to "Connected" without calling any external system. An owner would be told it is fixed when nothing was retried (inferred, packages/ranza/integrations/src/module.ts).

4. Top changes

  1. The link in the rail opens something usable. Align the rail gate with the page gate, and enable the capability on the demo Property so the screen can be checked. (INTEGRATIONS-01, S)
  2. Retry never tells me something is fixed when nothing was sent. Make it re-dispatch, or take it away until it does. (INTEGRATIONS-03, L)
  3. I can tell what to do about a failure. Plain title, plain cause, one action; raw text behind a disclosure. (INTEGRATIONS-08, M)
  4. I can trust "Last sync". Separate last success from last failure. (INTEGRATIONS-07, S)
  5. The page only claims what the system does. Drop "retries automatically" and "all in sync". (INTEGRATIONS-06, S)
  6. A person without permission is told so, not shown a clean bill of health. (INTEGRATIONS-02, -11, S)
  7. I know how to get my first channel connected. A real Connect flow, or an honest "contact support" line. (INTEGRATIONS-05, L)
  8. I can clear 30 failures without 30 clicks, and see history. (INTEGRATIONS-09, M)
  9. View-only people do not see a Retry button that cannot work. (INTEGRATIONS-04, S)
  10. I can see who retried what in the Audit log. (INTEGRATIONS-12, S)

5. Inconsistencies

  • Rail vs page: the rail offers Integrations to Owner and Manager, the page denies them (INTEGRATIONS-01). Sibling entries Configuration, Data export and Audit log sit in the same rail section; I did not open them, so I cannot say whether they have the same mismatch (unknown).
  • Denial wording: the same "not in your Subscription" text covers both "module off" and "you lack permission" (INTEGRATIONS-02). The brief and ADR direction is that denial is explained.
  • Edge-case doc vs UI: edge-cases.csv lists "Connect" (INT-S1-10) and attempt counting on failed retry (INT-S1-09); neither exists in the UI or module as described. All 15 rows are still proposed.
  • Test coverage: only a unit render test (tests/unit/integrations-view.test.tsx), a module unit test and a database test exist. There is no browser test for this screen (no integrations spec in tests/browser), which is how a rail link that opens a denial can ship.
  • Today does not surface integration trouble in "Needs attention" (verified on Today as Owner). An owner has to remember to open this page.

6. Not built / needs backend work

These are not UX defects. They are absent features, kept apart on purpose.

  • Any real provider connection (channel managers, payment providers, door locks, government reporting). docs/roadmap.md: "Channel and distribution integrations", "External payments", door locks are "Not started". Slice s2 in use-case.mmd (webhook receivers, rate and inventory mapping, door-lock keys) is explicitly "Not this slice".
  • Webhooks, API keys, credential storage, rotation and copy: no table, module function or UI. The roadmap lists "Public APIs, webhooks, integration..." as not started. The persona's secret-handling and "rotation consequences named before the click" checks therefore have nothing to test.
  • Producers of data: no code path calls connectIntegration or recordFailure (only scripts/db-seed-dev.mjs inserts rows, local only). Failed operations, Error states and "last sync" can only exist from seed data until adapters and an outbox consumer exist.
  • Automatic retry, expired-token, disabled and partial states, delivery log, health checks: not in the status model (connected | error | not_connected).
  • Placeholder cards for unbuilt providers: none exist. The page lists only rows in the database, so there is no "coming soon" catalogue; a never-configured Property sees only the empty sentence.

7. What already works well and must not regress

  • Rail hides it from Front Desk (verified): Front Desk's rail ends at Configuration, with no Integrations, Data export or Audit log.
  • Back button is present at the leading edge of the header in English, Turkish and Arabic and mirrors in RTL (verified; Turkish link targets /tr/today?property=..., ADR 0035).
  • All three locales are translated for the denial state, the page title and the rail; Arabic page is dir="rtl" (verified).
  • 375 px: header and message wrap correctly and the bottom bar appears (verified, 04), though this is only the empty state. The populated table at 375 px was not seen; the code wraps it in overflow-x-auto (inferred).
  • Security shape is sound in the database (inferred, migration): row-level security on both tables, insert and update need integrations.manage, no delete grant, column-level update grants. The raw-text and wrong-permission problems above are in the UI layer.
