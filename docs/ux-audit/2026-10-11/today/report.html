UX audit: Today (workspace landing dashboard)

Route /en/today · hosted staging (main 4b15c30) · 2026-10-11, about 15:05–15:15 Istanbul · persona: duty manager opening the shift · roles looked at: Manager (primary), Front Desk, Housekeeping, Owner · locales: EN, TR, AR · widths: 1280, 768, 375.

Disclosure about audit mode. Early on I pressed the Check in button on the arrival row of Today as Manager, expecting it to open a dialog. In the product it is a direct form submit (CheckInAction, one press). The server refused it ("That Reservation cannot be checked in."). Nothing persisted that I can see: Arrivals still read 0 / 1 checked in on every later load, as Manager, Front Desk, Housekeeping and Owner. I cannot see the audit log's view of a refused attempt, so if one was recorded it is mine. I did not press it again, and I pressed no other command button (Check out, Mark inspected, New booking submit). I also ran the browser offline for about 2.5 minutes on my own page (read-only, restored afterwards).

1. Verdict

  1. Could the duty manager use it unaided? Mostly yes. The first screen answers "what needs me" in about two cards, every number is a link, the clock and freshness line are honest, and nothing needed training. I did not hit a dead end or a raw error code.
  2. Biggest risk: the numbers disagree with each other or mislead. "Expected tonight 33%" and "Booked ahead, Oct 11: 67%" sit on the same screen for the same night. "Ready rooms 1 / 3" counts a room with a Guest still in it, so the manager is told a room is ready when no vacant ready room exists for the waiting arrival.
  3. "What happened overnight" is not answerable. Recent activity is the five newest records of any age (the visible ones go back to Sep 29), with no booking or Guest named, so it never reads as "since I was last here".
  4. Quick actions are a mixed bag. The one I tried from the arrival row was refused with a reason-free sentence, while the row itself labelled the room "Not ready".
  5. The page left open all shift does not warn when the browser is offline (it only warns when a request fails), so a stale 15:12 reading can sit under a 15:40 clock with no warning.

5. Inconsistencies with sibling screens and features

  • Housekeeping page says "Ready to let" / "Clean + Waiting for inspection"; Today says "Ready" / "Clean, awaiting inspection" and "Ready rooms". Same facts, three phrasings (verified).
  • Housekeeping's own "Ready to let 1" also counts occupied 102, so TODAY-02 is inherited from that screen's definition, not new on Today.
  • Departures page has "Due and overdue / Everybody in house" and a "Left today" section (0, "Nobody has left yet today"). Today's tile denominator excludes the overdue Guest that the list includes.
  • Arrivals shows balance "No Folio" for 201; Today's arrival row shows no balance. Not a defect, but Today never says a Folio is missing.
  • The Housekeeping page has the back button (seen in screenshot 02); Today (the root) correctly has none (ADR 0035). The Today header actor labels differ from other lists: raw emails here, display names in the greeting.
  • Rail shows 14 destinations to Manager but the movements, rooms, maintenance cards cover only 5; Housekeeping sees Finance/People/HR/Analytics in the rail (see TODAY-04).
  • Check in from Today is a one-press button; the feature doc (TD-S2-01) calls it "the Arrivals dialog". Check out does open a dialog, so the two commands behave differently under the same pattern.
