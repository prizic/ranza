UX audit: Configuration

Route /en/configuration (single page, 8 anchored sections, no sub-routes) · audited 2026-10-11 on hosted staging · roles: Owner (full), Manager and Front Desk (read-through) · locales EN, TR, AR · widths 1440 and 375 · mode: AUDIT ONLY, nothing was saved.

Method and limits. Verified = I saw it in the running app. Inferred = I read it in code or docs and did not press it. No Save, toggle or select-change was pressed anywhere; I opened pickers and typed draft values into the time-zone field only (local state, nothing sent except the read-only business-date preview) and left without saving. Staging data state: one Organization (Prizic Demo), one Property (Demo Otel İstanbul), currency already locked (TRY), 3 sellable units (2 Room, 1 Suite), no nightly prices set. Timings are estimates from the session, not stopwatch readings. Finance and Housekeeping roles were not opened (Unknown).

1. Verdict

  1. Day-to-day changes are usable unaided. The four Property settings, the Organization name and the nightly prices are clearly labelled, each says what it affects, Save is only enabled by a change, the business-date preview is useful, and read-only roles are told why (verified, all three locales render and Arabic mirrors correctly).
  2. First-time setup is not guided. The page is eight flat cards with no order, no “what is still unset” state, and no check-in/out times, taxes or default language to set at all. The one unset thing a new owner must act on (every unit type has no price, so bookings are taken free) is shown as quiet grey text.
  3. Biggest risk: two different save models on one page. Four cards need a Save button and silently lose edits when you leave; the Housekeeping and Maintenance cards save the instant a dropdown changes, including “Organization default” dropdowns that change every Property with no confirmation (inferred from code, not pressed).
  4. Smaller friction: the time-zone search cannot find a zone by country (searching “Turkey” returns Louisville and Yakutat, not Istanbul), the currency warns about permanence only after it is already locked, and at 375 px two maintenance dropdowns overflow their card.
  5. 13 findings: 0 block work, 4 cause errors, 4 slow me down, 5 polish. Eleven are verified in the browser (CONFIG-03 only in part), two (CONFIG-02, CONFIG-04) are inferred from code because pressing the control would have saved a setting or the state is not reachable on staging.

4. Top changes

  1. I can see at a glance what is not set up yet (unpriced unit types first, a count on the section chip). CONFIG-01.
  2. I can’t lose an edit by clicking away, and I can see which card has unsaved changes. CONFIG-03.
  3. Every setting saves the same way, and Organization-wide changes tell me how many Properties they touch before they happen. CONFIG-02, CONFIG-13.
  4. I find my time zone by typing my country. CONFIG-05.
  5. I am told the currency becomes permanent before the first booking, not after. CONFIG-04.
  6. On my phone I can jump to any section from anywhere and every dropdown fits. CONFIG-08, CONFIG-07.
  7. When I am blocked, the message is the same everywhere and names the permission, not a job title. CONFIG-06.

5. Inconsistencies

  • Within the page: Save-button cards versus save-on-change cards (CONFIG-02); two card anatomies (CONFIG-13); four read-only phrasings (CONFIG-06).
  • Pickers: the time-zone and currency pickers use a local SearchablePicker built from Command and Popover, while Staff, Audit log and Move guest use the shared Combobox from packages/ui. Different keyboard and matching behaviour is likely (inferred from imports; I did not compare them live).
  • Language: the interface language is chosen with the header “Language” menu or the URL (/en, /tr, /ar, verified by loading all three). Configuration has no language setting, so there is no confusion between the two today, but the owner who looks here for “languages” finds nothing. Whether the header choice is remembered across sessions: unknown, not checked.

6. Not built / needs backend work

These are not UX defects. Each is checked against the docs.

  • Guided first-time setup and a readiness checklist. Blueprint 19.2 specifies one (“readiness is visible as a checklist with owners, evidence, blockers”); docs/roadmap.md and the screens handover have no row for it. No CF-DEF-* row covers it either, so the gap is not recorded as deferred.
  • Check-in and check-out times, taxes, document settings. Blueprint 19.2 step 6 lists “taxes, accounting, and document settings”; blueprint 5.10 puts tax configuration in Accounting and Finance. No column or setting exists for check-in/out times and the Configuration edge cases have no deferred row for them (only CF-DEF-01 to CF-DEF-05).
  • Organization default language (CF-DEF-01): the column exists and nothing reads it.
  • Switching a capability on or off (CF-DEF-02), department or outlet scoped values (CF-DEF-03), adding or retiring a Property (CF-DEF-04).
  • Moving a trading Property to a new currency: ADR 0036 calls it a finance workflow and it does not exist.
  • “Rooms policy”: rooms and beds live on the Rooms screen, which Configuration links to (verified link present for Owner, Manager and Front Desk).

7. What already works well and must not regress

  • Section list beside the cards on desktop with the current section highlighted; chips on a phone; anchors work as links. Verified.
  • Save and Discard are disabled until a card has a change; a card saves only its own fields plus the other card’s saved values. Verified disabled; the rest inferred.
  • The live “Business date now / After saving” preview for time-zone and cutoff changes, with an explicit sentence for a move backwards. Verified preview; backward sentence inferred from the Turkish and English copy.
  • Currency lock with the reason shown beside the disabled picker. Verified.
  • Read-only roles see every value with a reason rather than a hidden page; the Manager gets a precise reason for the Organization name. Verified for Manager and Front Desk.
  • Turkish, English and Arabic all render fully, Arabic mirrors (back arrow, cards, list arrows), and the 375 px layout of the Property, Time and Rates cards is clean with no horizontal page scroll (document width 375 at 375). Verified.
  • Back button on the page, per ADR 0035. Verified.
