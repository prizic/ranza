  4. A blocked Unit refuses check-in at the database (trigger on stays), so the block is not UI-only. for share, not for key share: the FK already takes key-share, which a non-key UPDATE does not conflict with — the explicit lock is load-bearing.

  6. Bulk add shape: building (optional), floor (optional), first number (digits, width kept — 001 + 3 → 001, 002, 003), count 1–60, type, capacity 1–64, letByTheBed (rooms only, capacity ≤ 26, beds named A…Z, each inheriting the room's building and floor).

4. The pending fix in module.ts

unblockUnit currently reads the old reason with a correlated subquery inside RETURNING. PostgreSQL 17 (local, per docker/postgres/Dockerfile) has no RETURNING OLD, and relying on snapshot semantics in RETURNING is too clever. Replace with two statements in the same transaction: 

const [before] = await tx.$queryRaw<{ reason: string | null }[]>`
  select status_reason as "reason" from public.accommodation_units
   where id = ${unitId}::uuid and status = 'blocked'`;
// then the update without the subquery, returning organization_id, name
// audit context: { name, hadBeenBlockedFor: before?.reason ?? null }

Then pnpm --filter @ranza/accommodation typecheck (after pnpm --filter @ranza/db generate — a bare tsc fails without it).

7. Gotchas paid for today

  • G1 — Docker/compose. The one Postgres container belongs to compose project ranza-audit-log. From ~/Developer/ranza-rooms, reset it with docker compose -p ranza-audit-log down -v && docker compose -p ranza-audit-log up -d --wait && pnpm db:setup; a plain pnpm db:reset from this worktree would try a second container on port 54322. colima start first if docker ps cannot connect. A fresh connection through colima's port forward sometimes stalls (Prisma P1001) — retry, it is not the code.
  • G2 — pnpm db:migrate:new fails with a handed shadow DB ("function set_request_context already exists"): Prisma replays into SHADOW_DATABASE_URL twice within one migrate dev. Comment out SHADOW_DATABASE_URL in .env for that one command so Prisma makes its own temporary shadow, then restore the line. The migration for this slice already exists, so you should not need this again.
  • G3 — .env lives only in each worktree (gitignored); the rooms worktree has a copy. Integration tests do not load it: set -a; source .env; set +a first.
  • G4 — the definer sweep. tests/database/insert_grants.test.sql regex-scans every app security-definer function's source for insert /update /delete and pins the count and inventory. Keep prose outside $$ bodies; if you add a definer, update the count and the set_eq list deliberately.
  • G5 — RLS and UPDATE. An UPDATE whose row the policy's USING hides touches zero rows and raises nothing; only WITH CHECK and column grants raise 42501. Assert row counts or unchanged values, not exceptions, for "may not update".
  • G6 — pgTAP. A data-modifying CTE cannot sit inside a scalar subquery; run the statement at top level and assert afterwards.
  • G7 — PostgreSQL 17, so no RETURNING OLD.
  • G8 — the audit-log worktree has an untracked 27 MB docs/evidence/ that makes pnpm check fail on prettier. It is not in the PR; move it aside to run the gate there. Do not commit it.
  • G9 — the main checkout ~/Developer/ranza holds another session's uncommitted work (sidebar, deploy scripts, hosted-staging runbook). Do not touch it; work in the rooms worktree.
  • G10 — two pre-existing defects on main, reported not fixed: (a) under two concurrent browsers the workspace layout's per-capability entitlement check exhausts the pool (Prisma P2028); (b) frontDeskProperty falls back to another reachable Property when ?property= is not entitled, so disabling a capability shows another Property's data under the switcher's original label. (b) is in the blast radius of the new Rooms page, which will use the same helper — decide whether to fix it in this slice or name it in the PR.
