01 / Foundation

Platform Vision & Anti-Fork Doctrine

Traditional accommodation systems fork client codebases or sell separate products for hotels vs. student residences. Ranza rejects forks entirely. Every subscriber runs the identical release line; differences exist purely through branding, Entitlements, configuration, and permissions.

Single Release Line

One platform, one schema family, and one deployment pipeline. No custom customer branches, no bespoke database tables.

Entitlement Subscriptions

Front Desk, Housekeeping, F&B, Folios, and Analytics are toggled via database Entitlements without changing backend code.

Inviolable Baseline

Tenant isolation, row-level security, tamper-resistant audit logs, and data portability are platform rights, never paid safety upsells.

Authority Chain (§16): Higher-level documentation strictly governs lower levels: BLUEPRINT.md > docs/adr/*.md > Module Specs > Active Issues > Code & Tests. If code contradicts the blueprint or an approved ADR, the documentation wins and the code is defective.
02 / Domain Language

Canonical Vocabulary (No Pilot Language)

This repository originated from a student-dormitory pilot. That pilot vocabulary is completely superseded. CI source-text scanners (scripts/dependency-boundaries.mjs) reject commits using legacy terminology.

Forbidden Pilot Term Canonical Term Architectural Definition
Operator / Dormitory Operator Organization The legal subscribing entity that owns one or more Properties and holds commercial subscriptions.
Branch Property A physical site (hotel building, student campus, hostel) operated by an Organization.
Student Resident A long-stay occupant. (A Student is simply a specialized type of Resident).
tenant (in product language) Organization Use "tenant isolation" for database discussions; product and UI must always use Organization.
Room / Bed Accommodation Unit The sellable or assignable space (hotel room, private bed, studio suite, apartment).
Booking Reservation / Stay A Reservation is the planned future booking; a Stay is the active operational connection.
Bill / Invoice Folio The financial ledger for a Stay. Lines are append-only; balance is solely the sum of lines.
03 / Architecture

The Three-Tier Module System

Ranza cleanly separates reusable platform capabilities from hospitality-specific business logic. This separation is enforced by automated dependency checks.

Tier 1: Platform

packages/platform/*

Host-agnostic modules: audit, outbox.
STRICT RULE: Must not name Property, Guest, Resident, Stay, Reservation, AccommodationUnit, or Folio.

Tier 2: Ranza Domain

packages/ranza/*

Hospitality core: core, accommodation, reservations, stays, folios. Speaks accommodation language freely and owns private tables.

Tier 3: Adapters

packages/adapters/*

Translates Ranza concepts into generic platform contracts (e.g. folio-to-posting, stay-to-audit). Nothing may depend on adapters.

Dependency Injection Mandate (ADR 0006)

No package in packages/ (except packages/config) may read process.env or initialize a database connection. Packages declare dependencies via a deps object passed at the composition root.

The Server Funnel (ADR 0007)

In apps/operator-workspace, only src/server/viewer.ts is permitted to import @ranza/db or domain modules. UI components receive plain typed props and cannot issue queries.

04 / Security & Tenancy

Five-Gate Security & Database Roles

Access control is enforced at the PostgreSQL layer via Row-Level Security (RLS) policies. Application checks only supplement database enforcement.

Role: ranza_app

Runtime role used by Prisma client. Not superuser, no BYPASSRLS. Context set via app.set_request_context(user_id) inside each transaction.

Role: ranza_auth

Used by Better Auth. Reaches only credentials and TOTP secrets in auth_* tables. Has zero permissions on tenant business tables.

Role: ranza_worker

Background processor role. Operates under app.set_worker_context(org_id, job) to drain the outbox. Cannot impersonate user requests.

ADR 0012: A Policy Bounds Rows; A Grant Bounds Columns

RLS governs which rows may be updated using WITH CHECK. But RLS cannot restrict which columns are modified. PostgreSQL column-level grants prevent actions like check-out from maliciously altering room IDs or stay dates:

PostgreSQL Grant Enforcement 
REVOKE ALL ON public.stays FROM ranza_app;
GRANT SELECT ON public.stays TO ranza_app;
-- Check-out only needs to update status and ends_on. Any other column write is rejected by Postgres:
GRANT UPDATE (status, ends_on, updated_at) ON public.stays TO ranza_app;

06 / Data Model

Relational Model & Composite Keys

Composite foreign keys (id, property_id, organization_id) guarantee multi-tenant integrity directly in the database. A Stay or Folio cannot reference a Unit or Property belonging to another Organization.

organizations

Core

• id: UUID [PK]
• name: TEXT
• status: 'active' | 'pending'
• default_locale: 'tr'|'en'|'ar'

properties

Core

• id: UUID [PK]
• organization_id: UUID [FK]
• currency: CHAR(3)
• UNIQUE (id, organization_id)

accommodation_units

Units

• id: UUID [PK]
• property_id, organization_id [FK]
• unit_type: 'room' | 'bed'
• capacity: INT

reservations

Front Desk

• id: UUID [PK]
• accommodation_unit_id: UUID [FK]
• guest_name: TEXT
• starts_on, ends_on: DATE

stays

Operations

• id: UUID [PK]
• reservation_id: UUID [FK]
• user_id: UUID [Resident Link]
• status: 'in_house' | 'cancelled'

folios & folio_lines

Ledger

• id: UUID [PK]
• stay_id: UUID [FK]
• amount_minor: BIGINT (cents)
• Balance: SUM(amount_minor)

07 / Domain Invariants

Core Domain Workflows

Operations prioritize immutable audit trails and safe error recoveries over deletions.

Check-In & Reversal (ADR 0022)

What if staff accidentally check in the wrong guest? Operational history is never deleted.

Staff withdraw the check-in. The Stay transitions to status = 'cancelled', the empty Folio closes, and the Reservation returns to status = 'confirmed' so the guest can arrive again. A partial unique index ignores cancelled stays.

Financial Ledger Invariants (ADR 0015)

• Money is an integer: BigInt minor units (e.g. 10000 = $100.00). Never floats.
• Balance is solely a SUM: Folios store no balance column. Balance is always calculated dynamically from lines.
• Append-only corrections: No UPDATE or DELETE on lines. Corrections are made via a new line with line_type = 'reversal'.

08 / Decisions

Architecture Decision Records (ADRs)

All 23 approved decisions recorded in docs/adr/. Filter by architectural domain:

ADR 0001Database

Prisma owns schema, SQL owns RLS

Prisma handles schema migrations; RLS policies, triggers, and grants are hand-written SQL in the same migration file.

ADR 0005Security

Better Auth with provider indirection

Authentication provider subjects map to Ranza users via auth_identities, decoupling external providers from domain users.

ADR 0006Architecture

Modules take dependencies by injection

No package touches process.env or creates database connections. Host apps inject dependencies at boot.

ADR 0007Security

A session becomes a request context

Single funnel: Session ➔ User ID ➔ withOrganizationContext(). Apps never reach the database outside this transaction-local funnel.

ADR 0008Database

Module owns a schema, not migration history

Platform modules own dedicated PostgreSQL schemas (e.g. audit.records) with tamper-resistant append-only triggers.

ADR 0009Security

Resident reaches own Stay, not an Organization

Residents in Guest Portal access their row through separate resident RLS policies, never by widening staff permissions.

ADR 0012Security

A write is bounded by a policy, not a check

RLS WITH CHECK carries all 4 gates; PostgreSQL column grants restrict writable columns, preventing unapproved property or unit reassignments.

ADR 0015Financial

Money is an integer, balance is sum, correction is line

Amounts are BigInt minor units. Folios hold no mutable balance. Adjustments are append-only reversal lines.

ADR 0016Worker

Long-running process is worker, not 2nd backend

apps/worker is a standalone NestJS application context without HTTP listeners, controllers, or ports.

ADR 0017Worker

Cross-module facts travel through transactional outbox

Events are written to outbox.events in the same DB transaction as the business operation, then polled asynchronously.

ADR 0022Database

Mistaken check-in is reversed, not deleted

Withdrawn check-ins mark the Stay cancelled, close the empty Folio, and re-confirm Reservation for future arrival.

ADR 0023Architecture

Copy is ICU through next-intl, catalogue typed

All user-facing copy is typed and localized into TR, EN, and AR with automatic RTL support.
